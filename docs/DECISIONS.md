# Decisions

Settled. Don't re-open these unless the user explicitly asks. New decisions get a new row at the bottom.

| # | Decision | Why |
| --- | --- | --- |
| 1 | 2D side-view, one screen per arena (**superseded by 22**) | Bopl-style physics chaos, readable bosses, every player always sees the whole fight; 2D is far easier for AI to build and debug. |
| 2 | Online co-op with Netcode for GameObjects, built in from day one | Players are on separate PCs. Adding networking later would mean rewriting most systems. |
| 3 | Direct IP over Hamachi; the host (or a server-only build) runs the server | Free, no cloud services or accounts; 4 friends fit the free Hamachi plan. |
| 4 | Owner-authoritative player movement; server-authoritative everything that matters | Controls feel instant; HP, bosses, draft and run state stay consistent. Friends don't cheat. |
| 5 | Player attacks detected attacker-side, boss hits detected victim-side | What you see on your screen is what counts, so dodges always feel fair. |
| 6 | One networked `Game` scene; arenas are prefabs | Only one scene to keep in sync; swapping arenas is simple. |
| 7 | All tunable values in ScriptableObjects | You tune in the Inspector; the AI never hunts for magic numbers. |
| 8 | Combos only through tags and `ComboRules` | New abilities combine with old ones automatically. |
| 9 | No third-party tween or juice libraries | Fewer installs; small `Juice` helpers are enough. |
| 10 | Hitstop never touches `Time.timeScale` | On the host it would slow down the server for everyone. |
| 11 | 8 bosses at launch: 7 floors plus a final boss | Scope for version 1. |
| 12 | Pixel art, 640×360, 16 PPU, one fixed palette (**superseded by 24**) | Consistent look; AI-generated sprites must be palette-locked and cleaned. |
| 13 | Free Windows release on GitHub | No store approval; Steam stays possible later. |
| 14 | Claude Code (desktop app) as the main agent, Antigravity supported; Unity's MCP server (`unity mcp` from the Unity CLI) for both | The agent can read the console, run play mode and see the scene. `AGENTS.md`, `docs/CODE_STYLE.md` and the skills are shared, so either agent follows the same rules. |
| 15 | Abilities on left / middle / right mouse, aimed at the cursor (Bopl Battle style) | Precise aim is what makes combos and friendly chaos land. Keyboard and gamepad keep facing + tilt aim, and their `LaunchAngle` lob. |
| 16 | Light attack aimed at the mouse cursor (keyboard J); dodge roll goes any direction of the move input | Matches cursor-aimed abilities; up and diagonal rolls make dodges and boss weak points reachable. Gamepad attacks keep the facing way. |
| 17 | Faster, airier player movement with one air jump | Playtest: 4 players crowded on the floor and movement felt slow. A Bopl-like air game spreads players out and makes dodging bosses vertical. `AirJumps` can be set to 0. |
| 18 | Mouse melee is a slice: hold left mouse and drag across a target; mouse abilities fire on release | The primary button gets the most-used action without losing Ability 1 on left click. Cuts only count within reach of the player, so it stays melee. |
| 19 | Attack and ability controls are a player setting (Settings → Controls setup): keyboard + mouse (default), keyboard only, mouse only, or custom per action | Some people play with one hand on the mouse, some without a mouse; a custom scheme covers everyone else. The scheme is local to each player and never networked. |
| 20 | Nicknames: typed in the main menu, sent with the join request, cleaned and made unique by the server, synced as a player NetworkVariable; empty means P1-P4 | A client can send anything, so the server decides the final name. Names are for display only; slots (colour, hat) stay the identity. |
| 21 | Reopened on purpose by the user (2026-10-19): bigger maps with a panning camera, and Brawlhalla-style weapons, are wanted; decision 1 (one screen per arena) no longer holds for future arenas | Backlog items, not built yet. |
| 22 | Arenas are bigger than one screen, with a panning follow camera (2026-10-19). The camera frames the living players (plus a boss within `BossFocusRange`), never lets the local player get closer than `LocalMargin` to the view edge, is clamped to the arena prefab's `ArenaBounds`, stays pixel perfect at a fixed zoom, and is local presentation only. Edge markers show off-screen teammates, gravestones and bosses. The hub stays one screen. | Replaces decision 1. Wide arenas need the group to be able to spread out; a fixed zoom keeps the 16 PPU pixel art crisp and the view size identical for everyone, so telegraph readability does not depend on zoom. |
| 22 | Weapons are a free pick in the hub and at rest stops, not draft cards; every weapon is a move set (light combo, heavy, aerial, up, down) in a `WeaponData` asset, and Fists is the default | Keeps the ability draft about abilities and combos, lets friends try every weapon on the hub dummy, and stays out of `ComboRules`. The equipped weapon is server-owned state so every PC plays the same swings. |
| 23 | Keyboard and mouse are never active together for combat: schemes are Keyboard only (default), Mouse only and Custom (one device) | The user asked for it (2026-10-20); supersedes the keyboard + mouse default of decisions 15, 16 and 19. |
| 24 | (**superseded by 25**) Art style is a 1930s rubber-hose cartoon look inspired by Cuphead, never copying it (2026-10-20): AI stills + hand pass, Unity 2D Animation rigs stepped at 24 fps, 96 PPU art for a 40 × 22.5 unit view, flat cel fills with a mask-based player colour swap, a URP film look with a Settings toggle. PixelLab is no longer used. Gameplay, bosses and networking are unchanged. | The user asked for it. Rigs plus stepped playback get the hand-drawn feel without drawing every frame; the mask swap keeps one body for four players on anti-aliased art. Replaces decision 12. |
| 25 | Pixel art in a 1930s rubber-hose cartoon style, inspired by Cuphead but never copying it, made with the PixelLab MCP (2026-10-20): 960×540 base resolution, 24 PPU (view still 40 × 22.5 units), 48×48 player and hat canvas, 144–240 px bosses, 24×24 tiles, one palette with the 8.1 ramp-swap shader, a URP film look with a Settings toggle. | The user wants PixelLab and the cartoon look. More pixels than 640×360 give pie-cut eyes and gloves room to read; the view and gameplay sizes stay the same. Replaces decisions 12 and 24. |
| 26 | No red glow overlay on boss art (2026-10-21, the user): a boss telegraph is its wind-up pose and the sound cue, with the gold weak point in recovery. Extended the same day (the user): no red masks anywhere, so the red ground zone is gone too (`Telegraph` only draws the weak point). Hitboxes and ranges follow the drawn strike pose, not the other way round. | The user does not want glow masks on the art. The `Telegraph` glow parts remain only for bosses without art yet (Brood Mother, Bell Twins, test bosses) and are emptied when a boss gets its poses. |
| 27 | The game is called **Boplborne** and has a story harness (2026-10-21, the user): the tower is silent because its Grace Bell was silenced; the final boss, the Crowned Hollow, is a former pilgrim hollowed out by wearing every hat. Story is shown by an opening of five cards in the Hub, a tower cross-section ascent screen between floors, and ending cards. All cosmetic, local on every PC, skippable, never blocks gameplay or the network. Full text in `docs/LORE.md`. | The user asked for lore, an intro and floor transitions, and chose the "Hollow was a pilgrim" twist. One reusable ascent screen costs one asset instead of eight clips. |
